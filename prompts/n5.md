Implement ADR-0005 D7 / P5 — the **Windows single-file `.exe`** for the gateway-first
product. This is the last non-parked unbuilt item from an Accepted ADR (ADR-0005). Read
docs/adr/0005-gateway-first-charon.md D5 (security), D7 (packaging), and the P5 line in
the build sequence FIRST.

GOAL: a PyInstaller single-file `charon.exe` that starts `charon gateway` (loopback +
optional token) and is buildable on a **free `windows-latest`** GitHub runner in a
**separate** workflow that does NOT touch the Linux `[self-hosted, 4-lom]` CI.

BUILD:
1. `packaging/charon.spec` — PyInstaller spec bundling the existing `charon.cli:main`
   entry as `charon.exe` (gateway is the default-launched mode). The privileged core is
   stdlib-only; PyInstaller is a BUILD-time tool, never a runtime dep of `src/charon`.
2. `pyproject.toml` — add an OPTIONAL extra (e.g. `[project.optional-dependencies]
   packaging = ["pyinstaller"]`). Do NOT add pyinstaller to core deps. Do NOT add a
   `[project.scripts]`/entry change that pulls non-stdlib into the privileged path.
3. `.github/workflows/windows-exe.yml` — runs ONLY on `windows-latest`, triggered on
   tag/release or manual `workflow_dispatch` (NOT on every push; must not run on the
   self-hosted Linux runner). Steps: checkout, setup-python, `pip install .[packaging]`,
   `pyinstaller packaging/charon.spec`, upload the `.exe` as a build artifact. Smoke-step:
   run `charon.exe --help` (or `--version`) and assert exit 0.

CONSTRAINTS:
- Own ONLY: `.github/workflows/windows-exe.yml`, `packaging/charon.spec`, `pyproject.toml`.
  Do NOT touch any file under `src/charon/`, tests, or other workflows (ci.yml/heavy.yml/
  release.yml). If you discover the entry point needs a tiny shim, STOP and note it in the
  PR description instead of editing src — do not expand scope.
- The Linux gate must stay green and UNCHANGED: pytest, ruff check, mypy src tests,
  python3 tools/check_boundary.py src, python3 tools/check_version.py. Your change adds a
  separate Windows workflow; it must not alter the Linux gate's behavior.
- No keys/secrets in the repo or workflow. Loopback-default posture per D5 is unchanged.
- Conventional commits. Open a DRAFT PR with base = master (`gh pr create --base master
  --draft …`). Do NOT merge — the manager gates and merges.

ACCEPTANCE: the new workflow builds a `charon.exe` on windows-latest and the smoke step
(`charon.exe --help`, exit 0) passes; the Linux gate is untouched and green; pyinstaller
is an optional extra only; the diff touches only the three owned files.
