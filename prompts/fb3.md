Retire the shared-append docs/REVIEW-LOG.md in favor of PER-TICKET FRAGMENTS, killing the
merge-conflict class that occurs whenever two tickets append a review note in parallel
(it blocked S1 #27 vs E2 on 2026-06-27). Same fix-shape as per-droid mailbox files.

CONTEXT: today every ticket appends a dated section to the single docs/REVIEW-LOG.md. Two
concurrent tickets both append at EOF -> textual merge conflict, CONFLICTING PR, no CI.

GOAL: one fragment file per ticket; the shared log becomes a GENERATED artifact, never
hand-edited.

BUILD:
1. Create docs/review-log/ and MIGRATE the existing docs/REVIEW-LOG.md content into one
   fragment per dated/ticket section: docs/review-log/<id>.md (e.g. E1.md, E2.md, ...).
   Preserve content verbatim; do not editorialize. Keep a short docs/review-log/README.md
   explaining the fragment convention (one file per ticket; never edit another ticket's).
2. tools/render_review_log.py — stdlib-only: concatenate docs/review-log/*.md in a stable
   order (e.g. lexical, or a date prefix in each fragment) into the rendered docs/REVIEW-LOG.md
   with a generated-file header ("DO NOT EDIT — generated by tools/render_review_log.py from
   docs/review-log/*. Add your note as docs/review-log/<id>.md."). Provide `--check` mode that
   exits non-zero if docs/REVIEW-LOG.md is stale vs the fragments (for CI).
3. docs/REVIEW-LOG.md becomes the GENERATED output of step 2 (regenerate it; keep it in the
   repo as the readable rollup). Going forward droids write only their fragment; the manager
   (or a CI/pre-commit step) re-renders.
4. Wire `python3 tools/render_review_log.py --check` into the gate (.github/workflows) so a
   stale rollup fails CI. (If editing the workflow is out of scope for `owns`, instead leave a
   one-line note in the PR body requesting the manager add the CI step; do NOT edit files
   outside your owns.)

Tests: tests/test_render_review_log.py — proven-red: fragments render in stable order; the
generated header is present; --check passes on a freshly-rendered file and fails on a stale
one; an added fragment changes the output deterministically.

CONSTRAINTS: own ONLY docs/REVIEW-LOG.md, docs/review-log/* (the new fragments + README),
tools/render_review_log.py, tests/test_render_review_log.py — nothing else. Write your own
