Build wave 2 of Charon's native work-engine (ADR-0010): the scheduler. Read
docs/adr/0010-native-work-engine-substrate.md (D2 scheduler; the FENCE choke-point rule),
docs/DECISIONS.md (D008), and the ADR-0010 entry in docs/REVIEW-LOG.md FIRST. Depends on E1
(engine/board.py, engine/claim.py) already merged.

KEY FRAMING: workers are warm ACP agents driven by the EXISTING AgentBackend +
parallel.py ThreadPool. The scheduler is a coordination layer — it does not spawn or manage
processes.

GOAL: assign claimed board units to warm ACP-agent workers, concurrently, honoring waves +
budget + the fence.

BUILD:
1. src/charon/engine/scheduler.py —
   - Drain the board (engine/board.py): pick claimable units (deps done, no in-wave
     owned-path collision), claim them (engine/claim.py), run them concurrently over the
     existing parallel.py / AgentBackend warm-ACP substrate, bounded by SharedBudget.
   - CRITICAL (DTC Lens-2 R1 / D008): drive EACH unit through the EXISTING fenced
     coordinator.run (assert_environment + scrubbed_env + escape-scan + lkg/rollback). The
     scheduler MUST NOT be a second, unfenced dispatch path and MUST NOT call a backend
     directly — reuse coordinator.run as the single fenced execution unit.
   - Liveness = ACP-deadline + checkpoint-kill (ADR-0007 D8). NO process-group/PID machinery.
   - On completion: release the claim, advance board state. On failure: release for retry,
     respecting the claim epoch so a stale run can never land.
2. src/charon/engine/capacity.py — a small pluggable CAPACITY-LIMITER seam gating per-tier
   concurrency, with a DEFAULT **FixedCap** implementation (conservative per-tier cap from
   config) + a selector the scheduler consults. Do NOT implement AIMD here — just the seam +
   fixed default. AIMD plugs in later (ticket E10) by extending this file. (Building the
   seam now is justified: the AIMD consumer is committed — D016.)

Tests: tests/test_scheduler.py — proven-red: a unit runs THROUGH the fence (assert the
fenced coordinator path is invoked, not a raw dispatch); depends_on waves run in order;
disjoint units run concurrently; the capacity limiter bounds concurrency; a failed unit
releases its claim.

CONSTRAINTS: own ONLY src/charon/engine/scheduler.py, src/charon/engine/capacity.py,
tests/test_scheduler.py. Import board/claim/coordinator/parallel — do NOT edit them.
Stdlib-only core. Gate green every commit (pytest, ruff, mypy src/charon, check_boundary,
check_version). No secrets. Conventional commits. Add a docs/REVIEW-LOG.md note if a
non-trivial decision arises. Open a DRAFT PR base=master; do NOT merge.
