# SLOP coordinator doctrine — placement report

## Injection point chosen
`AGENTS.md` (repo root of mediastack) — added a new section **"## Coordinator operating
contract (any-model session)"** immediately after the "## Session start" block.

## Why this is THE reliable, model-agnostic point
- The bootstrap one-liner that starts EVERY SLOP session — defined in `SESSION-HANDOFF.md`
  (line 11) and generated by `handoff.sh` (line 28) — literally reads:
  "…read SESSION-HANDOFF.md fully, then **read AGENTS.md**, then run the gates".
  So AGENTS.md is loaded by explicit instruction, not by harness auto-load convention, which
  means it does not depend on which model/agent runs (Claude Code, opencode, or any ACP agent).
- AGENTS.md is the vendor-neutral file by design: its intro says "Your LLM routes through Charon;
  nothing assumes a specific model/vendor." `CLAUDE.md` was rejected because it only auto-loads
  for Claude Code, not for the other models SLOP sessions run on.
- Of the two files the bootstrap reads, `SESSION-HANDOFF.md` is transient regenerated state;
  `AGENTS.md` is the durable standing-orders file — the correct home for durable doctrine.

## Exact file edited (repo-relative)
- `AGENTS.md` — one new section added (additive; no existing lines changed).

## How a session loads it
Operator pastes / handoff.sh emits the bootstrap one-liner → session reads SESSION-HANDOFF.md
then AGENTS.md in full → the coordinator contract is in-context before any work begins.

## Public-clean confirmation
- The added section contains NO absolute paths, hostnames, IPs, secrets, or personal info —
  generic language only. Verified by scan.
- Bonus: `AGENTS.md` is **gitignored + untracked** in mediastack (a "LOCAL dev file — never
  commit", confirmed via `git check-ignore` / `git ls-files`), so it cannot leak into the public
  repo at all. (Its pre-existing "## Handoff" section already carries local /home paths — that is
  the existing local-only design, unrelated to my edit.)

## Blast radius (changes behavior of ALL top-level SLOP sessions)
- **Additive/safe:** pure insertion; no existing rule text modified.
- **Role tension (flagged):** AGENTS.md is fundamentally WORKER-framed ("You are a coding agent
  working tickets"). The coordinator contract says the opposite ("you are the coordinator, don't
  do the work"). I resolved this with an explicit **Scope** line: the contract governs only the
  top-level session the operator drives; a spawned worker sub-session ignores it and follows
  "The ticket contract" below. No hard contradiction remains, but a session that is BOTH driven by
  the operator AND told to "work tickets" now holds both framings — the scope line is the tiebreak.
- **Guaranteed load?** Guaranteed for any session started via the bootstrap one-liner, on any model.

## Launch paths that would NOT pick it up
1. Spawned **worker sub-sessions** — they get tight briefs, not the full bootstrap, and run in
   `.claude/worktrees/*` with their own per-worktree `CLAUDE.md`; they do not read root AGENTS.md.
   (This is intended — the contract is coordinator-scoped — but it means the delegation contract is
   not self-enforcing on the worker side; caveat (b) about structural enforcement still applies.)
2. Any session started WITHOUT the bootstrap one-liner (raw `claude`/agent invocation with no
   "read AGENTS.md" prompt) — nothing forces the read. The bootstrap is a prompt convention, not a
   hook, so it is only as reliable as the operator/launcher pasting it.
3. Fresh clone on another machine — AGENTS.md is gitignored, so it is per-machine local; a new
   checkout has no AGENTS.md until one is created locally.
