## THE -v2/-REDERIVE PATTERN (deep dive)

Five pairs exist: substrate-first-gate, coverage-meta-gate, stranded-work-detect,
github-limits-hardening, session-end-push-gate are each duplicated as -v2 or -rederive variants.
**Root cause: the landing flow's EXISTING-BRANCH GUARD** (`fleet/land.sh:151-161`).

When a branch already has commits not reachable from the manager's current HEAD (common after a
session branch lingers while master moves on), `land.sh` **refuses** to use it. The only paths are:
(a) `git checkout -B` to force-repoint the old branch (destroys its unique commits), or
(b) create a new branch.

Path (b) — creating `-v2` / `-rederive` — is the path of least resistance: no destructive
force, no risk of losing the old commits, and the naming convention signals intent. The old branch
persists with its SHAs intact, accumulating sprawl.

This mechanism explains the wider 164-rig-branch problem (of which these 16 are a sample).
The sprawl root cause ticket (BRANCH-SPRAWL-ROOT-CAUSE) should investigate a lifecycle fix:
either auto-archive the old branch when a `-v2` is created, or provide a sanctioned
`land.sh --reuse-branch` path that realigns rather than refuses.
