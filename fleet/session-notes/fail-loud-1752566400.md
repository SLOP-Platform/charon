## What was implemented
Hardened the terminal `all_providers_exhausted` synthesis in
`src/charon/forwarder.py` into a structured, legible OpenAI-compatible error
contract (owns forwarder.py terminal block only):

- **Structured 503 envelope** on full-chain exhaustion: adds
  `requested_model`, `no_provider_reason`, `retry_after_s`, and
  `providers_tried[]` — one entry per attempted provider carrying
  `{provider, status, reason, class, rearm}`.
- **class/rearm sourced from real routing state**: `_classify_provider()` reads
  `srv.balance_tracker.funding_class(provider)` (the routing-time source of
  truth) mapped to the canonical taxonomy (1=free-recurring, 2=flat-sub,
  3=drain-then-park, 4=PAYG) + per-class re-arm strings. Never hand-fabricated;
  unknown/absent config degrades gracefully to `("unknown","unknown")` so the
  field is always populated (never a 500).
- **Bounded Retry-After**: reuses `srv.retry_after_hint(ordered)` (clamped
  `[1, max_cooldown_s]`), no new unbounded value invented; header + body
  `retry_after_s` are the same value.
- **HTTP status**: 503 when chain had members but all exhausted/parked; 502
  (same envelope schema, empty `providers_tried`) when NO route configured.
- **4xx-relay distinction PRESERVED**: a genuine 400/401-bad-key/403 is relayed
  transparently — no synthesized envelope, no synthesized Retry-After.
- Retained `X-Charon-Provider` / `-Failovers` / `-Failover-Reasons` headers and
  legacy `failover_reasons` body field.

`tests/test_forwarder_fail_loud.py` (6 fail-on-revert tests): structured
`providers_tried` with all 5 fields + real balance-tracker classes; bounded
Retry-After (header == body, within `[1, max_cooldown_s]`); 4xx-relay on BOTH
solo and multi-provider pools (multi-pool locks the reachable synth path);
unknown-class graceful default.
