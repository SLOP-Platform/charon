## THEME 1 — Shared mutable state: ticket-id case is not canonicalized [HIGH]
Four findings collapse to one bug, with live corruption on disk now.

- **Severity:** HIGH (real, actively manifesting)
- **Location:** `/home/stack/charon-private/fleet/{submit.sh:6, done.sh:6, release.sh:5}` use the raw caller arg; `claim.sh:18-21,28` derives the id from the UPPERCASE board basename and does case-sensitive `[ -e state/submitted/$id ]` guards. `board.sh`/`status.sh` likewise key on exact case.
- **Impact:** Two divergent namespaces for one fact. Live: `state/claims/S1` (02:34Z) coexists with `state/submitted/s1` (02:21Z) — S1 was re-claimed 13 min *after* it was submitted because `submitted/S1 != submitted/s1` on Linux. `board.sh` shows S1 "claimed" while its PR is open (board lies). Orphans `submitted/{e0,fb1,n5,t8}` leaked permanently (done.sh rm'd the uppercase key). Re-claim → second worktree on same branch → duplicate/conflicting PR.
- **Fix:** Canonicalize once in every state script — resolve `$id` against `board/*.md` and reject non-matching ids so the marker filename is always the board basename. Add a `validate_board` invariant: every `state/{claims,submitted,done}` entry must equal a board basename exactly (else RED). Manually `rm` the live orphans (`submitted/{e0,fb1,n5,s1,t8}`, stuck `claims/S1`).
- **Ticket:** YES — top priority.

## THEME 2 — Preflight gate fails open [HIGH]
Three findings, one defect. The validator the RUNBOOK mandates passes GREEN on real collisions.

- **Severity:** HIGH
- **Location:** `/home/stack/charon-private/fleet/validate_board.sh:49-62`. The owns-collision branch (line 58) only `echo "  REVIEW ..."`, never sets `red=1`; `exit $red` (line 62) returns 0. Compounding bug: the loop is the tail of a `... | while read` pipe, so even setting `red=1` there dies in the subshell.
- **Impact:** Live run prints 9 collision lines then "GREEN board structurally valid / EXIT=0". The exact disease it was built to catch (capacity.py double-claim) does not fail the gate. Also `hasdep()` only checks DIRECT edges, so transitively-safe chains (e.g. `intake.py <- E4 E9`, E9→E8→E6→E4) get the same REVIEW label as genuinely-concurrent triples — training the operator to wave past all REVIEW lines.
- **Fix:** Move the counter out of the piped subshell (process substitution / temp file). Walk the dep graph **transitively**; a pair with no path → hard RED that sets `red=1` and fails exit. Keep REVIEW only for genuinely ambiguous cases (glob owns).
- **Ticket:** YES.

## THEME 3 — Shared mutable state: unsequenced same-file board ownership [MED]
Nine+ owns-collisions; this is the structural input to Theme 2. Grouped — same fix pattern.

- **Severity:** MED (latent; each fires only if both tickets of a pair run concurrently → git merge conflict at PR time, human-resolved)
- **Location:** `fleet/board/*.md owns:` — `cli.py <- E6 N2 S1`; `land.py <- E3 E8 N2`; `config.py <- E8 S1`; `fence.py <- S1 T7`; `validate.py <- E6 N4`; `decompose.py <- E9 N4`; `check_boundary.py`+`test_boundary.py <- E0 FB1`. None sequenced by a direct/transitive dep edge.
- **Impact:** Concurrent droids edit one file on independent branches cut from master → merge conflict or silent clobber (E8 = feat/auto-land is the silent-clobber risk on `land.py`/`config.py`). The "one writer per file" partition is unenforced for the busiest files. `cli.py` is the worst (triple-claimed, central dispatcher).
- **Fix:** Per-pair, either add `depends_on` edges to serialize (FB1→E0; E6→S1; N4→E6/E9; etc.) or split shared modules into per-feature seams owned by exactly one ticket (`cli/_land.py`/`_sandbox.py`/`_engine.py`; per-feature config dataclasses; scanners-core vs auto-land policy in `land.py`). Once Theme 2 is fixed these become launch-blocking.
- **Ticket:** YES (one ticket, repartition the board).

## THEME 5 — Rig state machine has no safe inverses / liveness [HIGH+MED]
Cluster of transition defects; the build harness diverges from its own engine reference.

- **submit has no inverse [HIGH]** — `release.sh:5` removes only `claims/$id`, never `submitted/$id`; `claim.sh:20` skips any submitted ticket. A closed-unmerged PR (live S1/E1) is wedged: claimed-clear + submitted-set, permanently un-claimable. RUNBOOK's documented recovery (`close PR; release.sh; re-run`) **cannot work**. Fix: add `reject.sh` (or have release.sh also rm submitted). **Ticket: YES.**
- **done.sh trusts operator, no merge proof [MED]** — `done.sh:1-7` writes the marker with no `gh pr view --json state==MERGED` / ancestry check. A premature/typo'd done immediately unblocks dependents (`claim.sh:27`) → they branch off a master lacking the dep code (build-on-sand). Fix: assert merge before writing marker. **Ticket: YES.**
- **No TTL/PID liveness on claims [MED]** — `claim.sh:28` stamps droid+timestamp only; nothing ages it out. A kill in the claim window (current set at fleet-droid.sh:22, after the claim is written at :19) leaks `claims/<id>` forever. Engine `claim.py:95-102` does `_is_live` reaping — port it. **Ticket: YES.**
- **Retry-forever, no attempt cap / no human-BLOCKED node [MED]** — `fleet-droid.sh:33-35` release→reclaim loops a hard-failing ticket indefinitely, burning spend. Engine has `max_attempts` (scheduler.py:290) + BLOCKED state (board.py:40). Add a `state/blocked/<id>` after N fails. **Ticket: YES.**
- **Multi-dep tickets break [MED]** — `claim.sh:26-27`, `board.sh`, `status.sh` read `depends_on` as ONE id; `validate_board.sh:34` and engine `board.py` split on commas. `depends_on: E1, E4` → tests `done/E1, E4` → permanent block. Latent (board is single-dep today). Fix: `tr ',' ' '` + require all done. **Ticket: YES.**
- State mutations not under the claim flock (LOW); empty/unknown tier claimable (LOW) — fix opportunistically, no ticket.

## THEME 6 — Git process: branch/PR lifecycle races [MED]
- **Stale remote branch on re-run [MED]** — `JOIN-PROMPT.md:11-16` retry cleanup is local-only (`branch -D`, no `push --delete`); reused branch name diverges from the lingering `origin/<branch>` of the closed PR → `gh pr create --fill` non-ff push rejected, no recovery step. (PR #27 onto feat/sandbox-policy required an out-of-band force-update — proves the gap.) Fix: `git push origin --delete <branch> || true` in cleanup, or unique per-attempt branch suffix. **Ticket: YES.**
- **Phantom PR-OPEN [MED]** — `fleet-droid.sh:30-32` gates `submit.sh` on the claude exit code only; `gh pr create` (JOIN-PROMPT:39) has no success check. submit marks PR-OPEN with no PR → manager waits forever on a non-existent PR. Fix: capture/verify PR URL before submit. **Ticket: YES.**
- **Trap-vs-PR race [MED]** — `fleet-droid.sh:13-16` cleanup releases when `submitted/$id` absent; submit runs *after* `gh pr create`. Interrupt in that window releases a claim while the PR/branch exists → re-claim collides on the branch. Fix: write a pr-open marker the instant the URL is observed; cleanup checks `gh pr view <branch>`. **Ticket: combine with above.**
- **Worktrees/branches never pruned [MED]** — `done.sh` leaves them; 15 live worktrees for done tickets, with non-canonical casing (`charon-fleet-E1` vs `-e0`) so a re-run's `worktree remove` can miss the dir and the next `worktree add` aborts. Fix: prune in done.sh + canonical dir names. **Ticket: YES.**
- **Scope self-check uses bare `master` [MED]** — `JOIN-PROMPT.md:34` diffs `master...HEAD` while branch creation correctly uses `origin/master`. When local master lags, the diff reports false off-scope paths → spurious abort. Fix: `origin/master...HEAD`. **Ticket: small.**
- **Concurrent `git -C <shared checkout>` race [MED]** — JOIN-PROMPT:12-15 runs fetch/`worktree add`/`branch -D` on one `.git` across parallel droids with no flock → intermittent packed-refs/ref `.lock` failures → churned retries. Fix: flock the git mutations or per-droid clone. **Ticket: YES.**
- **Droids bypass push deny-list [MED]** — `fleet-droid.sh:30` runs `--dangerously-skip-permissions`, so settings.local.json:198 `git push*`/`reset --hard*` deny rules are never consulted (compounds the known `git -C` glob bypass). The propose-default invariant is honor-system only. Fix: allowlist excluding push/reset; close the `git*push*` glob. **Ticket: YES (security-adjacent).**

## THEME 7 — Engine concurrency (shipped product, src/charon/engine) [HIGH+MED]
- **Reclaim two-holder race [HIGH]** — `claim.py:200-211`: reclaim does `os.unlink(path)` then `_create_exclusive()` with no lock and no re-validation between the staleness read (`_is_live`, :175) and the unlink. Two reclaimers reading the same stale record both become live holders on distinct worktrees — directly violating the docstring (:160) the fence exists to uphold. Narrow window (needs fresh-per-attempt worktree factory + concurrent same-unit reclaim), but it's the core fencing primitive. Fix: atomic CAS — `os.replace` stale→temp and proceed only if content still matches, or per-unit lock around unlink+create; re-validate staleness immediately before unlink. **Ticket: YES.**
- **Disposition.RETRY is dead [MED]** — `scheduler.py:128-130` calls `Ledger.create`, which raises if `ledger.json` exists (`ledger.py:136`). Every retry re-fails at ledger creation → RETRY loops to the attempt cap; `self._attempts` (:228) never resets across `drain()`. The whole resume/reclaim machinery is defeated for the in-process retry path. Fix: create-or-load in the runner; scope `_attempts` per drain. **Ticket: YES.**
- **Capacity slot leak + non-fresh default worktree [MED]** — `scheduler.py:292-304` catches only `ClaimContended`; any other `_claim` exception (factory mkdir/init, `StaleReclaim`, `BoardError`) propagates without releasing the slot acquired at :292 and tears down the whole drain. Fix: try/finally with a launched flag; make `_default_worktree_factory` unique per attempt. **Ticket: YES.**
- **Stale-epoch release tears down drain [MED]** — `scheduler.py:335-339` `_settle` lets `StaleReclaim` from `release_claim` propagate out of the `for fut in done` loop, aborting settlement of in-flight siblings (left CLAIMED). The exact double-exec case the fence detects crashes instead of logging-and-skipping. Fix: catch `StaleReclaim`, mark unit superseded, do NOT `_advance`, continue. **Ticket: YES.**
- Epoch fences only `release()`, never threaded into `coordinator.run` (LOW) — fix docstring or thread the token. No ticket; note in code.

## SYSTEMIC PATTERNS
One disease dominates: **a single fact maintained as two un-cross-checked representations, with the guard that should reconcile them either absent or failing open.** It recurs at every layer — board `owns:` vs prompt "own ONLY"; uppercase board ids vs lowercase on-disk markers; register "Settled" vs ADR "Proposed"; rig state machine vs the engine it's meant to mirror (the rig lacks the engine's TTL reaping, attempt cap, BLOCKED node, and create-or-load that the engine already implements). The second pattern is **gates that print warnings but exit 0** — `validate_board` REVIEW, phantom-PR submit-on-exit-0, `done.sh` trust-the-operator, board-add before prompt exists — so safety depends on a human remembering to look, exactly the failure mode (capacity.py double-claim, E10 launched-blind) the project keeps re-encountering. Third, **shared resources mutated without serialization**: one `.git` checkout and one self-hosted runner, both hit by parallel droids/PRs with no flock/concurrency control, plus claim/submit not sharing the one flock that exists. The fix posture is consistent: make every hand-maintained coordination artifact machine-validated, canonicalize keys at the single write boundary, promote advisory warnings to hard failures, and converge the rig onto the engine's already-correct primitives instead of maintaining two divergent state machines.
