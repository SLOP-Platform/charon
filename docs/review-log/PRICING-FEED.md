# PRICING-FEED review log

## Decisions made and why

**6 candidates evaluated live (2026-08-02):**

1. **pricepertoken.com** — ADOPT. MCP server confirmed live via HTTP JSON-RPC to `api.pricepertoken.com/mcp/mcp`. 7 tools, no auth, MIT-licensed MCP. Operator-specified MCP-first shape confirmed.
2. **TokenWatch (tokenwatch.wyrdwerk.com)** — ADOPT as PRIMARY. 993 models, 81 providers, 2-hourly refresh. API live confirmed (stats endpoint returned correct counts). Tier-1 because it sources from direct provider /v1/models endpoints (DeepInfra, Crof, etc.) not just aggregates. MIT licensed.
3. **BenchLM** — ADOPT. API confirmed live. Daily refresh. MIT licensed. Quality-index primary, pricing secondary.
4. **WhatLLM** — ADOPT but overlaps BenchLM. Both use Artificial Analysis Intelligence Index as source. Marked for deprecation if BenchLM covers the same data.
5. **cheahjs/free-llm-api-resources** — SKIP. Markdown list only, no API, no MCP.
6. **12britz/awesome-free-models** — SKIP. Same as above.
7. **LiteLLM static JSON** — ADOPT as fallback only. Already shipped (commit 3314989). Gap confirmed: deepseek-v4-flash MISSING from static file.

**Key finding:** Operator said "MCP-first" — confirmed pricepertoken.com has an MCP. All non-MCP candidates that are webpage-only were SKIP'd. The two that have APIs (TokenWatch, BenchLM) are both MIT-licensed with no auth.

**Cross-validation done:** TokenWatch's gpt-4.1-mini price ($0.40/$1.60) matches OpenAI published pricing exactly. TokenWatch covers models (glm-5.2, deepseek-v4-flash) that LiteLLM static JSON does not.

**Design decision:** Disagreement between feeds is a SIGNAL, not an error. Implementation contract requires logging disagreements. No averaging across feeds for the authoritative value.

## What I concluded by reading only

- WhatLLM and BenchLM share the same underlying data source (Artificial Analysis) — they are not independent corroborators.
- pricepertoken.com's pricing database is itself a feed (not a direct provider API) — must be cross-validated against TokenWatch.
- The LiteLLM static JSON role as fallback is correct but its staleness is structural (git-vendored, not refreshed by CI).

## What the brief got wrong

- "cheahjs/free-llm-api-resources" listed as a candidate — it is an informational markdown list, not a pricing feed. No machine-readable data.
- "12britz/awesome-free-models" listed as a candidate — same, informational markdown list only.
- "TokenWatch (github.com/WyrdWerk/tokenwatch — already verified live: 993 models, 863KB pricing.json)" — the JSON is NOT directly served. It is generated by GitHub Actions and pushed to the repo; the live API is at `tokenwatch.wyrdwerk.com/api/v1/`. The 863KB claim refers to the raw GitHub-hosted JSON, not the served API.
